**① 什么能改、什么不能改。** 开头的场景叙述是文案化处理，如果跟你真实经历不符，换成你自己那次踩坑就行；但下面这些是事实，改了就会被评论区拆穿，务必原样保留：

## 加在识别前的三层预处理

都是本地图像运算，不联网、不调 API：

1. 整图平均灰度 **< 100** → 自动反色；
2. 灰度标准差 **< 45**（浅灰字、水印字、低对比 UI）→ 对 LAB 的 L 通道再跑一次 CLAHE；
3. 小选区放大 **2–3 倍** 再送进模型。

![深色截图预处理前后的真实像素对比](https://q037180.github.io/SnapOCR/assets/compare-dark-ui.png)

右图是代码里 `_enhance()` 对左图跑出来的真实像素，不是画的示意图。我故意没放「识别结果对比」——挑一张对自己有利的截图当准确率证据没什么意思，欢迎拿自己的深色截图实测。

这三层你不用装我的工具也能用，拿去改自己的脚本就行。真正值钱的是「先判断亮度再决定要不要反色」这个判断，不是我这个 exe。

## 哦对，我把它做成了一个工具

SnapOCR，Windows 10/11 x64，MIT，免安装 7z。按 `Ctrl+Alt+Q` 框选，松开即复制到剪贴板。顺手还做了文件夹拖入批量队列（去重、上限 500 张）、PDF 逐页识别（带进度、可取消）、表格框选转 Excel、滚动长截图拼接、截图贴图钉桌面、框选即译（11 种语言）。

引擎是 RapidOCR / PP-OCRv6，栈是 Python + PySide6 + onnxruntime + OpenCV。1080p 全屏 CPU 约 7 秒，小区域基本秒出。

白底黑字的常规截图，Win11 截图工具的「文本操作」和 PowerToys 文本提取器就够用，真不用换。要说功能全，Umi-OCR 比我全得多。这个东西只补上面两个场景。

## 先说清楚，省得你下完才发现踩坑

- **只有 Windows 10/11 x64 有现成二进制**，没有 macOS 版；Linux / macOS 可跑源码，但全局热键要额外授权、长截图依赖 Win32 直接不可用。
- **离线边界**：内置简体中文模型，默认识别全程在本机完成、不上传任何截图；首次切换到繁中 / 英 / 日 / 韩时会联网下载对应识别模型（只下载、不上传），之后离线可用。另一处联网是可选的截屏翻译（把识别文本发给必应翻译 / MyMemory，可在设置里关掉）。
- **未做代码签名**，首次运行会弹 SmartScreen。Release 页附了 SHA-256，介意就 `pip install -r requirements.txt && python entry.py` 从源码跑，不用碰 exe。
- 单文件 exe 约 160 MB，每次启动都要自解压一遍；所以主推 onedir 结构的 **7z 绿色包**（约 114 MB），解压一次，之后直接运行、删文件夹即卸载。

## 最有用的不是 star，是一张你识别失败的截图

如果你也常被深色截图坑，最有用的反馈是：**原始截图（去掉敏感信息）+ 你期望的文本 + Windows 版本**，提到 issue 里，我照着调阈值。

## 6. 让文案真的有机会被看见（按优先级）

1. **一次只发一个主渠道**，今晚掘金；隔 1–2 天收完反馈再换平台、换标题、换开头，别同日群发同一段文字。
2. **首图必须本地上传**。掘金外链图会触发「转存失败」并把提示文本写进正文；先用编辑器上传 `assets/compare-dark-ui.png`、`assets/hero-15s.gif`，需要封面再用 `assets/social-preview.png`，最后贴文字。完整清单见 `READY-TO-POST.md` §1「配图」。
3. **前 2 小时回完每一条评论**，每条回复带一个具体追问（「你那是终端还是网页？浅灰字还是纯白？」）。评论层数比点赞更影响推荐。
4. **别在正文求 star、别写营销词**。技术社区对这两件事的反弹比对广告还大；仓库链接放结尾就够了。
5. **标题只改钩子，别改事实**。同一平台不要改标题重发；换平台时从 §1 换一条不同流派的标题。
6. **达标线**：≥5 条非熟人评论，或 ≥20 次 Release 下载，外加 10 条带具体场景的反馈。没达标先换钩子重发一轮，不要急着加功能——两周仍不达标，问题在楔子场景（深色截图是不是真痛点），不在文案。
