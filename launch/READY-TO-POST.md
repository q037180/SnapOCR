## 正文（复制下面整个代码块）

```text
Windows 11 截图工具的「文本操作」、PowerToys 文本提取器，日常抠字其实已经够用。我一开始也没想再做一个 OCR，但有两件事反复卡住我。

第一件是深色截图。我的编辑器、终端、大部分技术文档都是深色主题。框选一段代码或一段报错栈，常规 OCR 经常整行漏掉，或者只识别到一半——检测模型基本是按「白底黑字」训练的，深色背景配浅色字不在它的舒适区。以前的土办法是：截图 → 丢进图片工具反色 → 再拿去识别，三步，还经常调不好对比度。

所以我在识别前加了一层预处理：整图平均灰度低于 100 就自动反色；灰度标准差低于 45（浅灰字、水印字、低对比 UI）再对 LAB 的 L 通道跑一次 CLAHE；小选区放大 2–3 倍再送进模型。都是本地图像运算，不联网。首图右边是代码里 _enhance() 对左边跑出来的真实像素结果，不是画的示意图。我故意没放「识别结果对比」——挑一张对自己有利的截图当准确率证据没什么意思，欢迎拿自己的深色截图实测。

第二件是结果找不回来。剪贴板只记得最后一次。识别完粘贴到别处，过半小时想再要那段文字，只能重新截一次。现在每次识别都存进历史：关键词即时过滤、鼠标悬停浮窗看全文、双击再次复制，也能一键导出 txt / docx / pdf / md / xlsx。改动很小，但用起来差别很大。

顺手做的还有：文件夹拖入批量队列（去重、上限 500 张）、PDF 逐页识别（带进度、可取消）、表格框选转 Excel、滚动长截图拼接、截图贴图钉在桌面、框选即译（11 种语言）。识别引擎是 RapidOCR / PP-OCRv6，默认打包了简体中文模型，开箱即用、完全离线；切换到繁中 / 英 / 日 / 韩时首次会联网下载对应识别模型，下载后缓存在本地，之后离线可用。1080p 全屏大约 7 秒，小区域基本秒出。

几个我不想含糊的地方：

- 目前只有 Windows 10/11 x64 提供可直接运行的二进制；Linux / macOS 可以跑源码，但全局热键要 sudo 或辅助功能授权，长截图依赖 Win32 直接不可用。没有 macOS 版。
- 单文件 exe 有 160 MB，每次启动都要自解压一遍，所以我另外出了 onedir 结构的 7z 绿色包：解压一次，之后直接运行、不再自解压，删文件夹即卸载。
- 程序还没做代码签名，首次运行 Windows 会弹 SmartScreen。Release 页附了 SHA-256，介意的话可以自己从源码构建。
- OCR 本身在本机完成、不上传任何数据；会联网的只有两处：首次切换非中文语言时下载模型文件（只下载、不上传），以及截屏翻译把识别出的文本发给必应翻译 / MyMemory（免费接口，无需 API Key，可在设置里关掉）。

不是劝谁换工具——系统自带的够用就继续用。如果你也常在深色 IDE 里抠代码，或者需要回头找之前识别过的内容，可以试试。

最有用的反馈长这样：附上出问题的原始截图（记得去掉敏感信息）+ 你期望的文本 + 系统版本，提到 issue 里，我照着修。

仓库：https://github.com/q037180/SnapOCR
下载：https://github.com/q037180/SnapOCR/releases

（叫 SnapOCR 的项目有好几个，这个是 q037180/SnapOCR，MIT，Python + PySide6 + RapidOCR。）
```
