## 二、修复的缺陷

### 2.1 版本号没有单一来源（严重度：中，已修）

**现象**：`tools/make_portable_7z.py` 里写死 `VERSION = os.environ.get("SNAP_OCR_VERSION", "v1.0.0")`，`release.yml` 的 `workflow_dispatch` 默认值也是 `v1.0.0`，而 `app/config.py` 里**根本没有版本号**。

**后果**：本地跑打包脚本时忘记设环境变量，会产出 `SnapOCR-v1.0.0-win64.7z` 却装的是 1.0.3 的代码；手动触发 CI 同理。这类错误不会报错，只会安静地把错包发出去。

**修复**：
- `app/config.py` 新增 `APP_VERSION = "1.0.3"` 作为唯一出处；
- 打包脚本改为「环境变量 → `APP_VERSION`」顺序取值，都取不到直接 `SystemExit`；
- `release.yml` 新增 `Read APP_VERSION` 步骤，tag / 手填值与 `APP_VERSION` 不一致时 `throw` 失败；
- 窗口标题改为 `SnapOCR - 本地离线截图OCR · v1.0.3`，用户报 bug 不用再问「你用的哪个版本」。

### 2.2 打包脚本里的体积数字错误（严重度：低，已修）

`tools/make_portable_7z.py` 的 docstring 仍写「每次启动都要解压 155 MB 到临时目录」。实测（zip 中央目录逐条累加）为 **378 MB / 313 个文件**。已与 README / CHANGELOG / QA 报告统一。

### 2.3 静态检查唯一告警（严重度：极低，已修）

`tools/make_compare_image.py:53` 的 `S = "#ce9178"` 赋值后从未使用（配色常量重构后的残留），已删除。

### 2.4 依赖声明不完整（严重度：低，已修）

打包与出图需要的 `pyinstaller` / `py7zr` / `Pillow` 只写在 CI 的 `pip install` 行里，README 的「自己打包」一节完全没提，照做必然 `ModuleNotFoundError`。已新增 `requirements-dev.txt` 并在 README 补一句。

## 五、潜在风险清单

### P0（影响用户能不能用上，建议优先处理）

1. **没有代码签名**。SmartScreen 弹窗会拦掉相当比例的下载者，这是当前转化率最大的单点损失。EV/OV 证书年费约 $200–400；短期可考虑 Azure Trusted Signing（便宜但需企业资质）。
2. **单文件版仍作为下载项提供**，实测 13% 启动失败（退出码 127）。落地页已经解释并推荐 7z/zip，但仍有用户会点错。建议下个版本把单文件版降级为「仅 Release 附页提供」，落地页只留 7z / zip。
3. **核心算法零单元测试**。`stitcher.py`（长截图拼接）、`exporter.py`（docx/xlsx 导出）、`engine.py`（预处理阈值）目前只靠人工试。这三处恰恰是历史上出过 bug 的地方（419 秒导出、表格错列、动态内容断图）。建议至少给 `stitcher` 和 `exporter` 各补 3–5 个「输入样本 → 期望结构」的回归测试。

### P1（有明确代价，但可控）

4. **PDF 超长导出慢**（Qt 内部布局限制，10 万行仍慢），README 已标注为已知限制。
5. **`QThread` 未逐个 `deleteLater`**：退出路径靠共享 deadline 兜底，不会崩，但长跑会缓慢累积。
6. **依赖无锁文件**：`requirements.txt` 只有下界。某天 `onnxruntime` 或 `rapidocr` 发大版本，CI 与用户环境会分叉。建议加 `requirements.lock`（`pip freeze`）供 CI 与打包固定。
7. ~~**`启动.bat` 不校验 Python 版本**~~ → **已修**：脚本在装依赖前先检查 `sys.version_info >= (3, 10)`，不满足直接进入 `:OLDPYTHON` 分支，打印检测到的版本并提示删掉旧 venv 重跑；`requirements.txt` 顶部也注明 Python 3.10+。两条路径都实测过（3.12 正常通过、模拟旧版本正确拦截并返回退出码 1）。
8. **无 `pyproject.toml`**：没有 ruff/black/pytest 的统一配置，本地与 CI 的检查规则只能靠约定。

### P2（整洁性）

9. ~~`assets/` 与 `docs/assets/` 双份 7.3 MB~~ → **已消除**，副本删除、出图脚本直写 `docs/assets/`（见 §3.3）。
10. ~~`launch/` 放在公开仓库，含发布节奏与话术~~ → **已迁出**：10 份文案移到本地 `.workbuddy/launch-archive/`（不进版本库）；
    `winget` / `scoop` 清单因是结构化、需随版本升级维护的物料，改放 `packaging/`；
    仓库不再包含任何发帖指引、渠道策略或话术。
11. 缺 `SECURITY.md`、`CONTRIBUTING.md`：有 issue 模板但没告诉人怎么提 PR。
12. CI 未配 pip 缓存，每次重装约 100 MB 依赖。
13. v1.0.0 Release 内 8 张媒体图已无用（§3.2）。
